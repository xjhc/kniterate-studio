# Mixed-paisley baseline — incomplete historical evidence

## What worked

The issued 522-pass, 635,356-byte machine file is preserved as `out.kc`, SHA-256
`0be718de93c415b51ccb859d013a5578f4ff8c2e8cfffc0ce4bd380ee495acd3`.
Both `out.k` and `out.kc` re-emit byte for byte from the fixed experiment
request and the saved motif. This is separate from Studio's production diamond.
The SD-copy receipt confirms issuance of these bytes and ejection of the card.
It does not confirm the bytes the controller ran.

The upper orange/grey specimen in the linked photo appears to contain the
complete small/large/small motif arrangement. Its association with this file
is inferred from appearance and the last issued candidate. The lower orange
jersey is a different specimen, not the reverse face.

## What failed or changed

The widening edge looks loose/open in the one-face photograph. Individual
missed loops, stop count, interventions, actual settings and reverse-face
quality were not recorded. The file starts two empty rear needles at each
increase; that is a software observation, not a physical fault diagnosis.
There is no new machine run. `partial` means incomplete validation; it does
not say the operator stopped early. Run identity, times and edit status stay
unknown instead of copying issuance facts into them. No Knit-proven claim.

## Follow-up

Confirm the specimen/file association with the operator; obtain both-face
photos and any retained stop or intervention records. Keep this file as the
unchanged old-increase baseline for a later controlled comparison. Review
Gate 3's reversible design before emitting a new increase mechanism.
